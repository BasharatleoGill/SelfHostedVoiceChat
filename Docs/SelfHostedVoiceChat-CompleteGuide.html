1. Read this first

Documentation scope: this guide matches the currently available public source release 1.1.0. Radio channels use Name values and Team voice is present. The visual node cards below are precise Blueprint-style diagrams for quick recognition; use Unreal's right-click search to place the real nodes.
Authority rule: microphone capture and local device/mute controls belong on the owning client. Voice actor creation, server mute, team assignment, range limits, and packet validation happen on the server. Never send voice packets from a UI or gameplay blueprint directly.

2. Installation and mandatory setup

  1. Copy the SelfHostedVoiceChat folder into <Project>/Plugins/.
  2. Regenerate project files and compile. Enable the plugin when Unreal asks.
  3. Open Project Settings → Self Hosted Voice Chat. Keep defaults for first test.
  4. Configure Unreal Voice in Config/DefaultEngine.ini.
  5. Spawn exactly one owned voice actor per connected player.

3. What happens to every voice packet

Owning client
Captures PCM, detects speech, encodes
Server RPC
Packet size, rate, codec, mode, range and membership validated
Server router
Selects valid recipient voice actors
Target clients
Decode procedural audio and apply local mute/deafen

Dedicated servers only validate and route compressed packets. They do not initialize capture or playback audio.

4. Voice modes

Global

Every valid remote player receives the transmission. Start with Mode = Global.

Proximity

Only remote players within the sender's requested range receive voice. Set range first; server clamps it to MaxProximityRange.

Team

Only players with the same server-authoritative TeamId receive voice. Set teams from GameMode/server logic.

Radio

Named channel membership is server-authoritative. Join `Police`, `Squad_A`, or `Channel_10`, then start Radio capture using the same Name.

10. Blueprint patterns and common use cases

Push-to-talk — Global

Input Action Pressed → Start Voice Capture with Mode = Global. Released → Stop Voice Capture. Put input on the owning PlayerController/Character, never on GameMode.

Proximity chat

On the owning client, call Set Voice Range(2000), then call Start Voice Capture(Proximity). The server limits the range; test one player inside and one outside the range.

Team chat

On server GameMode logic, get each player's voice actor and call Set Team Id Authority. Then the player may start capture with Mode = Team. Ensure your game updates TeamId after team swaps.

Radio UI

When radio button is selected, call Join Radio Channel with a Name such as Police. Start capture with Mode = Radio and the same Name. When changing frequency, call Leave Radio Channel for the old Name first if you want single-frequency behavior.

Microphone settings menu

On widget Construct, call Get Audio Input Devices; add each Device Name to a ComboBox. On selection changed, call Set Audio Input Device. Show Get Selected Audio Input Device as the current selection.

Speaker/headphone settings menu

Call Get Audio Output Devices and populate UI inside its delegate. On selection, call Set Audio Output Device with Device Id. Handle the completion delegate before saving your UI selection.

Mute/deafen controls

For a player list, use each remote player's PlayerState with Mute Player. Bind your UI state to Is Player Muted. Use Set Deafened(true) for a local “hear nobody” switch.

Speaking indicator

After local voice actor is valid, get its VoiceComponent and bind On Speaking State Changed. Show microphone animation when true, hide it when false. This event represents the local microphone speaking state.

11. Testing and troubleshooting

No voice actor / capture false

Confirm GameMode spawned the actor, it is owned by correct PlayerController, and client waits for Get Local Voice Chat Actor validity.

No one hears voice

Confirm DefaultEngine.ini voice flags, matching audio settings, active capture, server mode switches, and recipient routing conditions.

Radio does not route

Channel names are exact Name values. Both sender and receiver must share the same channel Name. Confirm `MaxRadioChannelsPerPlayer` is not exceeded.

Audio is noisy or never talks

Test microphone device selection. Tune Input Volume and Speaking Amplitude Threshold. Lower threshold for sensitivity; raise it for background-noise rejection.

Release test checklist

  1. Compile a clean Development Editor build.
  2. Run listen server plus two clients: test Global, Proximity, Team and Radio both directions.
  3. Run dedicated server plus two clients.
  4. Test local mute, deafen, microphone/device swap and output-device swap.
  5. Test disconnect/reconnect and map travel.
  6. Verify Opus availability; use Raw PCM only as a diagnostic fallback.
  7. Package and test a Win64 build before distribution.
